# Overlay pages

The command line page and the hud page. The `overlay` Experiment mounts it as a remote `browser` element at the bottom of the main window (`src/chrome/parent_overlay.ts`). It is an ordinary extension page: it reads keys, draws, and sends messages to the background. It parses, completes and runs nothing itself.

| File | Role |
| --- | --- |
| `cmdline.html`, `cmdline.css` | The panel: the list of rows, the note row and the input line, in DesertFox's structure. `cmdline.css` holds only the search and confirm rules. The look is DesertFox's sheet (`vendor/desertfox/cmdline_style.ts`), which `cmdline.ts` adds to the page |
| `cmdline.ts` | Key handling and drawing. The page learns its window from `?window=<id>` in its address. It asks the background for the opening text (`cmdline.hello`), for rows on each edit (`cmdline.complete`), and sends the line on Enter (`cmdline.run`) or Escape (`cmdline.close`) |
| `hud.html`, `hud.css`, `hud.ts` | The second surface: the which-key panel and the toasts. It keeps no state: it asks the background for `hud.state` at load and each time it hears `hud.changed` for its window. The box is transparent and passes mouse clicks through. It never takes the keyboard |
| `confirm.ts` | The confirm prompt mode of the command line page: the y or n prompt a bridge write waits on (`src/background/bridge/confirm.ts`). It draws the lines as text and sends one `confirm.answer` |
| `line_edit.ts` | Pure helpers: apply a picked row to the text, move the highlight, split a name at the matched letters, move the list window, turn a wheel event into rows, pick the prompt and the note text |

## Keys

- Enter runs the line. While a folder or tag word is typed, the first row is highlighted and Enter takes it in place of the word, unless the word is already a whole value. A line that is not a command stays open with the reason in the note row, in the error color. An edit clears it.
- Escape closes the list first and keeps the line, as in DesertFox. With no rows, or the list already closed, it closes the line. Typing or a row key shows the list again, and a completion answer that was on its way when Escape came does not. Enter with the list hidden runs the typed text, not a hidden row. A click runs on the rows it showed and is dropped if new rows arrived. It works from any element. The page has no `<title>` in its markup and sets one after its input has the focus (or its confirm prompt shows). The host reads the title as "ready": until then the browser has the id `OVERLAY_LOADING_ID`, so the key runtime holds plain keys, and the title event with exactly that title (or a timer, if it never comes) gives it `OVERLAY_BROWSER_ID`, which the key runtime counts as a typing target. The page decides its own Escape while it is ready. The host (`on_escape_key` in `src/chrome/overlay.ts`) closes the overlay at once when the page has no title (it is not ready), and 300 ms after an Escape that the page does not answer by changing its title (it hangs). An Escape that only hid the list is the answer. The background asks the Experiment to unmount, which returns the focus to the thread list.
- Tab, <C-n> and <A-Down> put the next row in the line, and S-Tab, <C-p> and <A-Up> the previous one. Both wrap, and a single match goes in at once. After the first row key, Up and Down put the next or previous row in and stop at the ends. Every key puts the row in the text, so Enter runs what the line shows. The page keeps C-n and C-p from Thunderbird's new message and print. History loads before the first completion request, so a failed request does not skip it.
- The list draws at most 10 of the ranked rows, as a window that follows the highlight, with no scroll bar. The wheel moves the window by 3 rows a notch and a click on a row puts it in the line like Tab. Columns are command, description, flags and keys. The name column is as wide as the widest visible name (at most 28 characters). The keys column and the per-row `usage` are fields of the row (`keys`, `usage`): the page draws what the background sends.
- The note row sits above the input and is hidden while it has nothing to say. It shows a message (error, search count), else the selected row's usage, else the typed command's usage, else `no match`.
- The prompt is the `cmdline_prompt` setting (`caret` draws `> `, `colon` draws `:`, other text as it is). The background sends it in `cmdline.hello`. A search line draws `/ ` or `? `.
- The right end of the line holds the status widgets of the `statusbar_widgets` setting (`Inbox [23/30]`: the folder, then the row place). The page asks for them with `cmdline.widgets` once the completion rows are drawn, so the read that loads the folder pane script never delays the focus. They are a snapshot of the moment the line opened and are drawn once. A search line and a confirm prompt show none, an empty list leaves the area hidden, and a window under 30rem wide hides it (the vendored sheet). A long folder name is cut with an ellipsis at 20 characters.
- Up and Down walk the history while the line is fresh (nothing typed and no row key used) or has no rows, as in DesertFox. The history is the list `desertbird_cmdline_history` in `storage.local`. The background writes it when a line runs (`src/background/cmdline/history.ts`). The page keeps a copy that refills on `storage.onChanged`. The cursor is `vendor/desertfox/history_cursor.ts`.

- A confirm prompt (`hello.confirm` set) hides the panel and wears the panel's class for its colors, and runs no command line, completion or history. Only the background's answer to `cmdline.hello` picks the mode, at load. `y` answers yes, `n` and Escape answer no, and every other key does nothing. Keys in the first 300 ms after the prompt shows and repeats of a held key are ignored. The answer goes once. A `stale` reply (the prompt timed out or the background restarted) closes the page.

- A search line (`hello.search` set) shows `/ ` or `? ` as the prompt, draws no rows and has a transparent page, so the list narrows in view. Up, Down, C-n and C-p walk the search history. Tab does nothing. The browser of the command line is transparent for this.

## Rules

- The hud browser is told no size limit (`max_width` and `max_height` of 0). A browser that is told one resizes to its content, and a page of absolutely placed pieces has none, so the browser shrank to 0 by 0 (measured). The box is 520 px high and as wide as the window. The browser carries `transparent="true"`: without it Thunderbird paints the page canvas white.
- Colors come from the theme tokens (`--desertfox-*`, from `src/shared/follow_theme.ts`, which reads the theme the background publishes). The hud page keeps short local names (`--surface`, `--text`) that alias the tokens. The command line page uses the tokens directly. A page in the window follows Thunderbird's scheme through `prefers-color-scheme`, not the OS scheme (measured). The panel draws with DesertFox's own sheet and column chooser (`vendor/desertfox/whichkey_style.ts` and `whichkey_layout.ts`, added to the page as a `<style>`): a framed panel, a title chip with the chain of group names, keys in the secondary color, an arrow, bold group labels, rows filled left to right, and a footer of `ESC close` (the panel has no back key). Its font, scale and radius stay at the sheet's fallbacks, since the published theme holds role colors only. The panel and the toasts sit at the bottom right, as in DesertFox: right 16 px, the panel 44 px and the toasts 48 px above the window bottom, the toasts at most 40ch wide. The panel draws over a toast.
- The panel never cuts its rows. `choose_columns` (at most 20 rows a column and 4 columns) picks the column count from the height of the page.

- A confirm prompt borrows the command line surface, because only that surface takes the keyboard and gives the focus back. A prompt replaces an open command line in its window and ends its session. A command line that opens or closes in that window ends the prompt as a no. When the prompt ends, the surface goes, so the window is left with no command line.
- Sender text in a prompt is set with `textContent` only, never as markup. A program with the user's rights that can type keys into the window (a tool such as `wtype`) can still press `y`. No design inside the add-on stops that.

- The message shapes are in `src/shared/protocol.ts` (`CmdlineRequest` and its answers). Import it for types only.
- A key typed in the first moments after `:` can reach the list before the overlay has the focus, because the mount is a round trip. The overlay's `browser` has an id the key runtime treats as a text field (`src/chrome/overlay_id.ts`), so every key after the focus moves belongs to the page.
- The box is 280 px high and the page is transparent, with the panel at the bottom, so the panel's height follows its rows and nothing paints above it. The transparent part of the box still takes mouse clicks. The colors are the `--desertfox-*` tokens from the theme, set on the panel (`follow_theme(".desertfox-cmdline")`) over the sheet's hex fallbacks. The font is the sheet's (12px monospace). The mount tells the browser no size limit (`max_width` and `max_height` of 0, as for the hud), so the page spans the window width. A limit made the browser shrink to its content, 800 px wide.
