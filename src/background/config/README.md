# Config

The settings and the user's key bindings, kept in `storage.local`. The background page and the options page each build a store from `store.ts`.

## Files

- `store.ts`: reads and writes three keys. `desertbird_config_version` holds the data version, `desertbird_settings` holds only the settings the user changed, `desertbird_user_keymap` holds the user's normal-mode bindings. The memory copy refills on read and drops on `storage.onChanged`. A read that began before a change never fills the copy. A write leaves the version key alone: the next read stamps it, after any migration.
- `settings.ts`: the settings DesertBird stores, a subset of the vendored table plus the settings only DesertBird has (`message_scroll_step_px`, the step of `j` and `k` in a message, default 40, and `mode_indicator_style`, `classic` or `badge`, default `classic`). It also overrides the vendored `mode_indicator` default: `always`, so the mode label shows in normal mode too. `Settings` and `SETTING_DEFAULTS` there are the full type and defaults. Each has a kind that checks its value. The toast times are whole numbers from 500 to 30000, `which_key_skip` holds key sequences in keymap notation, and `hint_letters` (default `asdfghjkl`, as in DesertFox) holds two or more distinct letters without `/`, all as DesertFox checks them. A pick lowers the letters it reads. `notify_new_mail` (default `false`) switches the new-mail notifications, and `notify.toggle` flips it. `theme` (default `oasis_moonlight`) is one of the 16 Oasis themes and is published by `src/background/theme/`. `bridge` (default `false`) lets the native bridge host connect and run the commands the bridge allows (see `src/background/bridge/`). `bridge_share_folders`, `bridge_share_headers`, `bridge_share_bodies`, `bridge_share_attachments` and `bridge_share_contacts` (each default `false`) let the bridge read folders, message headers, bodies, attachment names and sizes, and the name and address of contacts. `bridge_share_contacts` also needs the optional `addressBooks` permission, which the options page asks for at Save. `bridge_allow_drafts` (default `false`) lets the bridge save drafts. `bridge_allow_actions` (default `false`) lets the bridge archive, trash and move messages after a yes on a prompt in Thunderbird. Each does nothing while `bridge` is off. `external_editor` (default `false`) lets Ctrl+E open the message of a compose window in the editor the native host runs (see `../external_editor.ts`). It does not depend on `bridge`. `compose_send` (default `false`) lets `g S` in a compose window send the message through Thunderbird's own Ctrl+Enter command. While it is off the key runs nothing. `notice_show_subject` (default `true`) puts the message subject in the snooze-wake and follow-up notices. Turn it off to keep subjects out of toasts and desktop notifications. `cmdline_prompt` (default `caret`) is the prompt of the command line: `caret` draws `> `, `colon` draws `:`, and any other text of up to 8 characters draws as it is. The options form keeps its leading and trailing spaces. `statusbar_widgets` (default `["folder", "position"]`) lists the widgets at the right end of the command line, in order: `folder` is the displayed folder and `position` is `[n/m]`, the current row over the rows the list shows. The options form takes comma-separated names and flags an unknown one. Its kind, `choice_list`, is the twin of the upstream `enum_list`. Stored values that are unknown or mistyped are ignored and reported.
- `migrations.ts`: `MIGRATIONS` holds one step (version 2: clamp and round `toast_ms` and `toast_error_ms`, drop `which_key_skip` entries that are no key sequence). A change to the stored shape adds one step, which turns version `n` into `n + 1`. Data with a newer version than the add-on knows is read as it is and its version is not lowered.
- `keymap.ts`: the default bindings with the user's on top (`effective_keymap`), compiled through the vendored compiler. A `null` binding removes a default key. The stored keymap has a second section, `menu`, for the keys that move an open menu (`menu.down`, `menu.up`, `menu.left`, `menu.right`). It is optional, so data written before it reads as it is and needs no migration. `sanitize_user_keymap` keeps menu commands in `menu` and drops them from `normal`, so a menu key never replaces a mail-tab key.

## Flow

`main.ts` hashes the effective keymap, compiles it, stores the tree and calls `keys.install`. A write to the user keymap key drops the copy and installs the new tree, with no restart. The matcher reads no setting, so a settings change does not reinstall anything. The settings are stored and read from the table for the consumers that join later.

No native host reads a config file yet, and there is no reload command. A change on the options page applies at once.
