# Chrome runtime

The privileged part of the add-on. It runs as the parent script of the `keys` Experiment, inside the Thunderbird process, and listens for keys in the main mail window. The schema is [`../experiment/keys.schema.json`](../experiment/keys.schema.json). The call shapes are in [`../shared/protocol.ts`](../shared/protocol.ts).

| File | Role |
| --- | --- |
| `parent_keys.ts` | The entry of the `keys` API: `get_keys_api` and `shutdown`. Holds the one runtime and the event subscribers |
| `platform.ts` | The Thunderbird globals the parent reads, and the guard that rethrows `ExtensionError(message)` from each verb |
| `focus.ts` | Where a key is going: a text field, the pane that holds the focus, the reading pane (and whether the body script is live in it) or an open menu. Follows the focused element through shadow roots and into browser documents |
| `runtime.ts` | Key handling. Takes its Thunderbird access as `RuntimeDeps`, so tests use fakes |
| `parent_overlay.ts` | The entry of the `overlay` API (`mount`, `unmount`, `onClosed`). Builds the remote `browser` element and loads the command line page into it |
| `overlay.ts` | Mount, replace and remove logic per window over `OverlayDeps`, so tests use fakes. A second mount replaces the first. A tab change or a closing window removes the overlay and fires `onClosed` |
| `overlay_id.ts` | The element ids shared by the overlay parent and the key runtime. The hud has ids of its own, and so does the mode label |
| `mode_label.ts` | The mode label at the start of the status bar, over `ModeLabelDeps` so tests use fakes. `set` finds the elements with the label id, keeps one, removes the rest and draws the text and colors for the mode and the style. It reads focus for insert mode and redraws on focus events. `shutdown` removes the label from every main window |
| `motions.ts` | The fixed motion table: `motion.down`, `motion.up`, `motion.top`, `motion.bottom`. Pure functions over a `ViewPort` |
| `parent_folderpane.ts` | The parent of the `folderpane` API, a bundle of its own that Thunderbird loads on the first call and not at startup. Its verb `fold` opens or closes the selected folder (`row`), every folder (`all`) or closes the selected folder or else its parent (`parent`), and answers false, doing nothing, unless the folder pane has the focus. Folder tree verbs belong here, not in `parent_keys.ts` |
| `app_verbs.ts` | The verbs `paneFocus`, `appCommand` and `appOpenPage` of the `keys` API. Each reads its target from a fixed table (pane focus targets, the one allowed command name with its controller, the three pages with their addresses), so no caller passes a function name or an address. `paneFocus` also takes `left` and `right`, counted from the pane `focused_pane` names, and refuses a collapsed pane or a message pane with no live body script |
| `view.ts` | The thread list of `about:3pane` (`gDBView`, `threadTree`) behind a `ListPort`: the rows for the motions and the selected message ids for background commands. Also the check that the front tab is the mail tab, and `mail_pane_of`, which names a window by id and returns the `about:3pane` of its front mail tab, and `view_verbs`: the verbs `viewRows`, `viewThread`, `viewAllThreads` and `viewScroll` of the `keys` API, which read and move the list for background commands. `viewRows` also returns the message flags word of each row, which the step commands read. `ListPort.select_range` sets a range for visual mode |

Four files know Thunderbird's own markup, so a Thunderbird rename lands in one of them:
- `view.ts`: `gDBView`, `getSelectedMsgHdrs`, `threadTree` and the tab mode `mail3PaneTab`.
- `app_verbs.ts`: `folderTree` (`selectedRow`, `expandRow`, `collapseRow`), `paneLayout` (`folderPaneVisible`, `messagePaneVisible`), `messageBrowser`, `commandController`, `DefaultController`, `openAddonsMgr`, `openContentTab` and `browsingContext.topChromeWindow`.
- `focus.ts`: the element ids `folderTree`, `messageBrowser` and `messagepane`, the element names `search-textbox` and `menulist`, and the popup `state`.
- `platform.ts` and `parent_keys.ts`: `#tabmail`, the `messenger.xhtml` URL and the window type `mail:3pane`. `parent_keys.ts` also reads `folderTree` (`rowCount`, `selectedIndex`) for the motions in the folder pane.

## Rules

- The `overlay` API has its own bundle, script and schema, and its own size guard. Its verbs take a window id and a surface name from a fixed list (`cmdline`, `hud`), and `setModeLabel` takes enums for the mode, the indicator and the style. The command line takes the keyboard and leaves on Escape or a tab change. The hud never takes it, stays across tab changes and goes only with its window or an `unmount`. One window holds one box per surface. The parent maps the name to a page of the extension and never takes a path or an address.

- Each Experiment API needs its own bundle, script and schema. Two manifest entries that shared one script left the second API unloaded.
- Import only the matcher side of `vendor/desertfox`: `keys/matcher`, `keys/token`, `prefix_tree` and `register_names`. Never import `registry/*`. Import `../shared/protocol.ts` for types and the body handoff attribute only, and `../shared/keymap_tree.ts` for the tree reader.
- `keys.install` takes the keymap as data. `root` is the branch of the normal mode. A leaf runs in the chrome only when its id is in the motion table. Any other id does nothing.
- With the folder pane focused, the motions move the folder selection (`folderTree.selectedIndex`, which also opens the folder) and not the thread list. Visual mode does not apply there. A background command still reads the thread list selection.
- A leaf with `runs_in: "background"` leaves as a `keys.onInvocation` event. Nothing else crosses the boundary, but the typed prefix: a `pending` event rides the same event with the typed key tokens (counts left out) and no keys when the sequence ends, so the background can list the keys that may follow. A tab change or a window blur is not reported, because `keys.js` is at its size budget: the background hears those itself. The event carries the MailExtension ids of the messages selected at the key press (`messageIds`), read in the same key handler, so a `j` typed right after `x` cannot change what `x` archives.
- The ids come from `gDBView.getSelectedMsgHdrs()` (a collapsed thread counts as all its messages) and `messageManager.convert`, which builds a whole message header for each one. The cost grows with the selection: a select-all over a very large folder stalls the key press for that long. Motions never read the selection and stay fast.
- The first `keys.install` registers one `ExtensionSupport` window listener. Later calls replace the tree and add no listener. `shutdown` removes every key listener and the window listener, and drops the tree and the half-typed sequence.
- Keys run only in the mail tab of the main window. A key passes through when a menu or panel is open, or when its target, its original target or the end of the focus chain is a text field (the quick filter, the global search). The thread list and the folder pane run keys. The overlay's `browser` is treated as a text field by its id (`overlay_id.ts`), so no key runs while it has focus. In normal mode an unbound plain printable key is swallowed. Unbound named keys (Enter, Escape, arrows, Tab, Space) and unbound chords (a key with ctrl, alt or meta) pass. A bound chord runs and is cancelled, like a bound plain key. With focus in the reading pane, no key runs a command. While the body script is live in the message body (it marks the document, see [`../content/README.md`](../content/README.md)), every key passes to it. Otherwise every plain printable key is swallowed and chords pass, so Thunderbird's single-key shortcuts do not fire there either.
- A half-typed sequence and a pending count end on any chord the keymap does not bind as its next key, and when a key goes to a text field, an open menu, the reading pane, another tab or another window. A chord the keymap binds as a first key then runs. A change of the front tab ends them too, however it happens (a `TabSelect` capture listener on the window), because a click on the tab bar sends no key. A blur of the window itself ends them as well (a `blur` capture listener on the window that ignores a focus move between elements), for example on an alt-tab.
- `.` is the command `repeat.last`, which `runtime.ts` runs itself and the motion table does not hold. It replays the last leaf that ran, motion or background, with the count it ran with. A count before `.` replaces that count. A replay reads the selection at the `.` key press, not the one the first run had. `.` never records itself. The last leaf lives only in chrome runtime memory. It is not user data and nothing can refill it, so the runtime that `shutdown` drops takes it along. The background tags steps of a command defined with `repeatable: false` (`msg.move`, `msg.snooze`, `msg.undo` and `cmdline.open`, among others) in the tree. Running such a leaf clears the last run, so a stray `.` never moves mail to a typed folder or snoozes it. `.` does repeat `x` and `d d`, with their count, because `u` undoes them. A `.` that breaks a half-typed sequence ends it and then runs as a first key, like any key the matcher retries.
- Visual mode is `visual.toggle` (`v`), which `runtime.ts` runs itself. It keeps one anchor row. While it is on, a motion selects the range from the anchor to the new current row through `select_range`. A background leaf reads the whole range as `messageIds` and ends the mode, so `x` or `d d` acts on it once. A leaf of a command with `repeatable: false` still clears `.`, and `v` never records itself. `v` again ends the mode on the current row. Escape does the same, but only while the mode is on: otherwise it passes through, so the command line overlay and Thunderbird keep it. A tab change or a window blur ends the mode. So does any key that finds another current row, another view or other message keys at the two ends of the range than the mode last set (a click, new mail, a row inserted or removed inside the range, a sort or a folder change), or that goes to a text field or the reading pane, so a stale anchor never reaches into a changed list. After a command takes the range, the selection collapses to the current row, so a following `d d` acts on one message. That collapse can show the row in the message pane and mark it read. A range over collapsed threads includes their hidden replies, as in Thunderbird.
