# End-to-end run

Drives the built add-on in a real Thunderbird and a real Betterbird, headless. It reuses the session and fixture modules from [`tools/measure/`](../measure/README.md) unchanged. Needs `labwc`, `wtype`, `wlrctl`, `grim`, `zip`, `unzip` and `node`.

```bash
tools/measure/fetch_thunderbird.sh      # once: Thunderbird 153.7.0 ESR into $MEASURE_DIR
npm run e2e                             # setup proof: start each app, take one screenshot
npm run build && npm run e2e -- --xpi dist/desertbird.xpi    # the key assertions, both apps, both profile kinds
E2E_KINDS=default npm run e2e -- betterbird --xpi dist/desertbird.xpi
```

With `--xpi` the run installs DesertBird and the helper add-on, prints one PASS, FAIL or NOTE line per check and writes `report.json` and the screenshots under `$E2E_DIR`. A FAIL exits non-zero. A NOTE is a measurement with no pass condition. `E2E_KINDS` picks profile kinds (`default`, `reply_no_identity`, `mail_account`, `message`, `message_remote`, `quick_reply_plain`, `quick_reply_html`, `mode_label_badge`, `mode_label_off`, `mode_label_themed`, `own_pages`, `compose_editor`, `compose_editor_html`, `compose_editor_html_top`; the three `mode_label_*` kinds compare against `default`, so list it first). `E2E_ONLY=mode_label` runs only the label checks. The two message kinds run the body script checks in the pane, a message tab and a message window; `message_remote` lets mail load remote content. `quick_reply_plain` and `quick_reply_html` give the identity a signature and install a copy of the xpi that seeds the quick reply slots at startup, then check that `g r 1` keeps the quote and the signature. The `own_pages` kind installs a copy of the xpi that opens the options or help page when the helper add-on sends its name (another add-on may not open them through the tabs API), then checks that `q` closes each page and does not close the options page with an input focused. The `compose_editor` kind turns on `external_editor` and writes a `desertbird_host` manifest and an `editor.toml` with a fake editor into the session's own `HOME`. The manifest points at the DesertFox host in `~/.local/share/desertfox/desertfox-host`, or at `E2E_DESERTFOX_HOST`. It checks that Ctrl+E, Ctrl+O then `e`, and Escape then `e` in a plain-text reply write the fake editor's text into the body, that `e` in insert mode types a letter, and that the mode label is in neither the body nor a saved draft (`save_draft_raw` of the helper). `quick_reply_html` checks the same of a saved HTML draft. With no host there it prints a NOTE and checks nothing. The two `compose_editor_html` kinds compose in HTML and their fake editor writes Markdown with a bold word, an `onerror` image, a `javascript:` link and escaped tag text. They check that the Markdown comes back as HTML in the user's place, with the quote and the signature kept and nothing live from the Markdown: below the quote in a reply for `compose_editor_html`, above the quote and the signature for `compose_editor_html_top` (`reply_on_top`, signature above the quote). Each records the bodies before and after the editor as NOTE lines, the source of the fixtures in `test/compose_bodies.ts`. `compose_editor_html` also saves a draft with an embedded image, opens it again and records the image `src` as a NOTE. A forward is not driven: `g F` in this profile opened its window only after many seconds, with the focus in the To field. Give each parallel run its own `E2E_DIR`.

The run opens the Inbox with keys only: seven Tabs reach the Local Folders row, Right expands it, Down opens the Inbox and F6 moves focus to the thread list. With a message shown, one F6 from the list reaches the message body and Shift+F6 returns. F6 cycles the folder pane, the thread list, the message body, the spaces toolbar and the global search on both apps, measured through the focus chain. Counted Tabs are not used: on Betterbird three Tabs from the folder pane end on a column header.

The follow-up checks set a reminder with `m f d`, read the stored record from the IndexedDB file of the add-on in the profile (the helper cannot read another add-on's storage), restart the app, and cancel with `m f c`. The due fire needs a clock run of a day and `src/` takes no test hook, so it is a hand check.

A reload or restart of DesertBird is a restart of the app on the same profile (`restart` in `harness.mjs`), because `management.setEnabled` is refused for an add-on in the profile folder and `src/` takes no test hook. `restart_app` in `run.mjs` records a check that the process id changed, so a skipped restart fails the run.

The two `mode_label_*` kinds install a copy of the xpi that seeds a setting at startup (`mode_label_badge` the badge style, `mode_label_off` the off indicator) and check the label against the strips the `default` kind (classic style) left. The label is an element of the window and no page, so the checks compare the pixels of its strip (`LABEL_STRIP`): `v` and Escape, and focus in and out of the quick filter, change it and bring it back. A disable or reload of the add-on is not run, because `management.setEnabled` is refused for an add-on in the profile folder. Unit tests cover the cleanup (`test/mode_label.test.ts`).

The `mode_label_themed` kind seeds the badge style and the `oasis_sol` theme, then reads the badge fill pixels (`png_colors`) against the theme's mode roles for the scheme the status bar shows. `E2E_THEME=tb_dark_os_light` or `tb_light_os_dark` sets Thunderbird's scheme against the OS scheme, so a label that follows the OS fails. `E2E_ONLY=cmdline` runs only the command line checks (`run_cmdline`). `E2E_ONLY=hints` runs only the mail window hint checks (`run_window_hints`). The labels are fixed per app in `WINDOW_HINT_LABELS`, read from the shots. `E2E_ONLY=search` runs only the `/` and `?` search checks (`run_search`). `E2E_ONLY=hud` runs only the which-key, toast and help checks (`run_hud`), after the Inbox opens. `E2E_THEME=dark` or `light` starts the app with that built-in theme and puts the name in the hud screenshots. `E2E_CONSOLE=1` prints the app and add-on console to `app.log`. The hud checks compare the bottom 80 px of the window (`shot_region`): the same selection with no panel draws the same pixels.

Betterbird is `/usr/bin/betterbird`. Override a binary with `--binary thunderbird=/path`. Scratch files go to `$E2E_DIR`, default `/tmp/desertbird-e2e/<app>/<profile kind>/`. `E2E_STARTUP_MS` (default 30000) is the wait after launch.

| File | Role |
| --- | --- |
| `profile.mjs` | `build_profile`: Local Folders, one identity, the fixture Inbox (its threads open collapsed) and the prefs an unsigned Experiment xpi needs. Kind `reply_no_identity` leaves the account without an identity. Kind `mail_account` adds a default POP3 account with a main and an alias identity, and gives Local Folders none. `install_xpi` copies an xpi into the profile under its gecko id |
| `helper/` | Test-only add-on, never shipped. Its content script `body_report.js` reports the scroll position and the selected text of each message document and whether DesertBird marked it live. It polls the sink for a command and answers with the selection, the displayed messages, the folders, every message flag and the windows, read through standard MailExtension APIs. It shows a fixture folder with a tagged and an attachment message, applies a quick filter or sort through the API, closes compose windows, opens and closes a popup window to blur the main window, opens and closes a second main window, reads and clears the clipboard text, selects a message by Message-ID (`select:<id>`), and archives or deletes the selection through the API to measure what Thunderbird leaves selected, and records folder display events, shows a folder by path and looks a folder up by account and path |
| `reading_fixture.mjs` | The Reading folder: tall plain, HTML, remote content and sandboxed frame messages for the body script checks |
| `harness.mjs` | `start_app`: starts the app in its own labwc session. `press` sends wtype arguments after a bare Shift, `shot` takes a grim screenshot, `ask` sends a command to the helper add-on and returns its answer, `read_state` reads the last thing the helper posted, `folder_message_ids` reads a folder's mbox |
| `run.mjs` | The runner. `run_cmdline` drives `:`, Escape, a typed command and `m t`. Without `--xpi` it only proves the setup. The key assertions run after `--xpi` |
